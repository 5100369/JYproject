# 在线更新（2.8.0 起）

## 使用方式

- 顶部“在线更新”入口：检查新版、查看公告、下载或暂停、打开安装包目录、确认安装。
- 正式版启动后延迟 5 秒检查，默认发现新版后空闲自动下载；两项开关可以独立关闭。检查失败不弹出阻塞窗口，不影响离线混剪。
- 新配置默认源为 GH-Proxy、GHFast、GHProxy 加速与 GitHub 原站；已有下载源设置保留，可点“补充预设加速源”。支持修改前缀、调整优先级、增加加速源或国内签名清单地址，最多 8 个源。公共服务的额度、条款与大陆速度需持续验证，不能保证所有地区可用。
- 开发版不自动检查、不自动下载、不执行安装；手动检查与下载可以测试。安装动作必须在正式版验证。
- Windows 下载的是现有 NSIS 安装包，确认后打开安装向导并退出当前应用，不是强制静默安装。失败启动安装向导时保留当前软件。
- Mac 先下载完整 DMG，确认后打开磁盘映像，由用户退出软件后拖入应用程序；没有开发者签名、公证和 Mac 实机验证前，不宣称支持完整无人值守自动替换。
- 生产、排队、压测和停止清理阻止安装；下载中生产开始会暂停，空闲后继续。手动暂停后不会自动恢复。
- 停止的未完成任务可下载更新，但安装会警告：旧任务续跑记录不能跨软件/后端重启恢复，已有成片与使用记录不删除。
- 已下载数据仅保存在应用自己的 `update-cache`，设置单独存为 `update-preferences.json`；不修改混剪配置、素材、输出或使用记录。
- 下载前检查磁盘余量，为安装及原软件保留至少 512 MB 或安装包两倍大小的余量（取较大值）；不足时阻止下载，不持续填满系统盘。

## 发版前如何测试

开发版“在线更新”里直接点“进入更新演练”，再点“检查更新”“下载 / 继续”。虚拟版本固定显示 999.0.0，内容为 1 MB 本地随机数据，落盘为 `test-data.bin`，不是安装包、不走公网。使用真实下载状态机、断点写入及 SHA256 校验，可在下载中暂停再继续；演练文件和设置与正式更新隔离，不能打开为安装包或安装。退出演练恢复原更新状态与下载源。演练仍服从实际混剪/压测的暂停约束。

可选场景：正常下载 / 暂停续传、主源失败后备用源回退、清单签名错误（应不下载）、文件校验错误（应不进入安装）。演练只验证流程与异常保护，不代表真实网络速度，也不替代正式安装回归。

“下载源与自动更新设置”里点“检测全部源”，检测当前编辑的地址，不自动保存。GitHub/代理源以已发布的 2.7.1 Windows 安装包为基准，请求前 1 KiB，只检查文件头后取消读取；另检查签名清单。因此能够区分“下载链路正常但清单 404”和真正超时、拦截页、签名错误。国内副本仅检查清单，不宣称安装包链路已验证。服务器忽略 Range 时也及时取消，不主动下载整包；实际在途字节由网络缓冲决定。

界面显示的“响应时间”包括 DNS、TLS、HTTP 及文件头返回，不是 ICMP ping，也不等同于整包吞吐。可手动按响应时间排序，保存后改变备用源顺序。每次至多并行检测两源，每源总限时 8 秒；只由用户触发，生产忙时不启动，批次间生产开始即停止。

## 发布操作

1. 首次带更新器的正式版仍需用户手动安装一次。现有 2.7.1 不含更新器，也没有 `update.json`；检查现有 Release 显示“未取得签名更新清单”是预期边界。
2. 继续按原流程构建 Windows EXE 与 macOS DMG、上传 Release、完成文件校验及更新公告。
3. 当前采用本地签名：核验两个安装包已上传且有 GitHub SHA256，然后执行下方脚本上传签名 `update.json`，私钥不离开本机。维护者必须在公布在线更新可用前验证公开清单。
4. 可选 `publish-update.yml` 自动签名发布，但须仓库所有者明确授权将私钥配置为 Actions Secret `VIDEOMATRIX_UPDATE_PRIVATE_KEY`；未配置时跳过，不能视为清单已发布。本地签名私钥只保存在 Git 忽略的受控发布目录；不要复制到客户端、提交、输出到日志或传给镜像。请安全备份，不能任意重新生成，否则已安装客户端不再信任新清单。
5. 可在最终发版时使用本地发布脚本（不输出私钥）：

   ```powershell
   $env:VIDEOMATRIX_UPDATE_PRIVATE_KEY = Get-Content -LiteralPath '.release-tools/update-signing/private.pem' -Raw
   $env:VIDEOMATRIX_GH = (Resolve-Path '.release-tools/gh/bin/gh.exe').Path
   node scripts/update-release.cjs publish vX.Y.Z
   Remove-Item Env:VIDEOMATRIX_UPDATE_PRIVATE_KEY
   ```

6. 若签名 workflow 失败，Release 安装包仍可手动下载，但不能报告在线更新已生效。发布后验证清单签名及资产，再完成客户端旧版→新版的真实安装回归。

## 国内副本与加速

- 代理模式：对固定 GitHub 清单和资产 URL 增加 HTTPS 前缀，失败重试一次，再切换下一个源；不传 GitHub Token。不支持 Range 的源会从头下载，不把完整响应追加到断点文件。
- 国内副本模式：自行托管同一发行版的两个安装包，按平台规则、额度和大小限制提供 HTTPS 下载。发布时可配置 `VIDEOMATRIX_UPDATE_ASSET_BASE_URL=https://example.com/downloads`，生成的安装包地址为 `<base>/vX.Y.Z/VideoMatrix.Setup.X.Y.Z...`，再将签名清单同步到国内地址。此设置不会自动上传到任何外部平台。
- 客户端必须验证内置 Ed25519 公钥对应的清单签名，再核对文件大小和 SHA256。HTML 错误页、空内容、错误字节范围、损坏包、旧版本、缺少平台包都不进入安装阶段。
- 发布脚本固定每版本安装包 URL，不读取可变分支源码，不在运行中替换 Python 文件，保留原前后端版本握手校验。
- 只流式读取、落盘、校验安装包，不全量读入内存；进度通知节流，后台任务查询返回布尔值与计数，不携带日志和配置。下载与校验会暂停，不增加混剪转码、解码步骤。
